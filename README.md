## 🗂️ Repository Structure

Each problem is stored in its own file, named with the pattern:

**`LC<problem_number>-<Problem Name>.cpp`**

This makes it easy to identify the problem directly from the filename.  
Each file contains the **full C++ solution code**.

### Example Layout
- **Path Sum (LeetCode 112)**
  - `LC112-Path Sum.cpp` → C++ implementation checking if a root-to-leaf path equals target sum

- **Path Sum II (LeetCode 113)**
  - `LC113-Path Sum II.cpp` → C++ implementation collecting all valid paths

- **Stone Game VIII (LeetCode 1872)**
  - `LC1872-Stone Game VIII.cpp` → Dynamic Programming solution (recursive, tabulation, optimized)

- **Smallest Missing Multiple of K**
  - `LC-Smallest Missing Multiple of K.cpp` → Hashing + loop approach

---

## 🔎 Notes
- Filenames follow the **LC<number>-Problem Name** convention.  
- Each `.cpp` file contains the **complete working solution**.  
- Explanations (intuition, approach, complexity, dry run) are provided in the repo’s main README and/or individual problem notes.
